# 物品信息数据约定

所有物品保存在同一个数组中。每条记录包含：

| 字段        | 含义                                       |
| ----------- | ------------------------------------------ |
| id          | 每条信息的唯一编号                         |
| type        | `lost` 表示寻物，`found` 表示招领          |
| name        | 物品名称，搜索时使用                       |
| category    | 物品类别                                   |
| description | 外观特征等描述                             |
| location    | 丢失或拾取地点                             |
| eventTime   | 丢失或拾取时间                             |
| contact     | 发布者提供的联系方式                       |
| status      | `active` 表示处理中，`resolved` 表示已完成 |
| ownerId     | 发布者在当前浏览器中的标识                 |
| createdAt   | 发布时间                                   |

状态显示规则：寻物的 `resolved` 显示“已找到”；招领的 `resolved` 显示“已归还”。

首页和搜索结果只展示未完成的信息，排除 `resolved` 记录；首页先过滤已完成记录，再取最新三条，搜索数量也只统计未完成记录。已完成记录继续保留在“我的发布”中，撤销完成标记后重新进入首页和搜索结果。

发布页的名称、分类、时间、地点、外观特征、联系方式均为必填项，提交时去除首尾空白。`eventTime` 支持原型中的文字时间（如“9月26日 下午三点”），也兼容已有演示数据的 ISO 时间；`createdAt` 由程序生成 ISO 时间。

发布记录保存在当前浏览器的 `localStorage.shiguang_items_v1`，发布者标识保存在 `localStorage.shiguang_owner_v1`。新记录初始状态为 `active`。保存成功后更新首页和搜索列表，“我的发布”按发布者标识筛选；保存失败时保留表单内容并提示重试。当前数据不在不同浏览器或设备间共享，清除浏览器数据会删除本地发布记录。

“我的发布”展示当前发布者的记录数量、信息卡片和空状态。未完成的寻物记录可“标记已找到”，招领记录可“标记已归还”；已完成记录可“撤销完成标记”，恢复为 `active`（寻找中／等待认领）。状态保存成功后更新“我的发布”、首页、搜索及详情中的状态文案。更新时校验存储记录的 `ownerId`，只修改所选记录的 `status`，保存失败时保持原状态并提示重试。

自己的发布记录可通过“编辑信息”修改类型及六个表单字段。编辑沿用发布页的必填及长度校验；保存时保留 `id`、`ownerId`、`createdAt` 和最新存储中的 `status`，替换原记录，不新增重复记录。取消修改不写入存储；进入编辑前尚未提交的新发布内容在结束编辑后恢复。保存失败时保留修改内容供重试。

“我的发布”支持全部、处理中和已完成状态筛选。三个统计数始终基于当前发布者的全部记录计算，列表数量显示当前筛选的结果数；标记完成或撤销后立即刷新统计和当前筛选列表。首次进入默认显示全部，本次页面会话内保留所选筛选。没有发布记录与筛选无结果分别显示对应空状态，筛选无结果可一键查看全部。
